# ADR 0002: Validation wave 1 research tooling

Date: 2026-11-03. Status: proposed, owner review.

Context: assessment `fx_ai_engine/docs/2026-11-03-system-assessment-and-benchmark.md` §4.1, §4.2 and §4.4, and plan `fx_ai_engine/docs/plans/2026-11-03-full-development-and-ai-plan.md` builds E3–E6 and decision D3. Branch `research/validation-wave1`, based on `hardening/2026-11` at 4d7bec2. The tools are offline and read-only: they never place, size or route orders, never write to the bridge folder and never change a risk constant.

Numbering: if `hardening/2026-11` also adds an ADR 0002 before this branch merges, renumber this file at merge.

| # | Decision | Adopted |
| --- | --- | --- |
| V1 | Location | New package `fx_ai_engine/research/` (`bias_audit` R1, `authenticity_gate` R2, `cost_stress` R4, `monte_carlo` R5, `common`). Tests in `fx_ai_engine/tests/test_research_*.py`. Hypothesis cards in `fx_ai_engine/docs/research/hypotheses/`. No existing file is edited; `run_replay.py` integration is described in `fx_ai_engine/docs/research/validation-wave1-integration-notes.md`. |
| V2 | R1 decision fingerprint | `generate_candidates(..., decision_times=[t])` funnel key, signal and regime dicts without `trade_id`/`timestamp_utc`, plus `(adv.approved, adv.reason_code, pm.approved, pm.reason_code, pm.final_risk_percent)` from AdversarialAgent and PortfolioManager, called as `simulate()` calls them. Truncation drops bars with `open + timeframe > t`; corruption (`random` ×U(0.9, 1.1) with random spread, or `nan`) alters exactly those bars, including the partially formed H1/H4/D1 bar. |
| V3 | R1 warm-up thresholds | Parity (c1) is blocking: the replay must serve `min(requested, closed)` bars for every agent request; the requested lengths observed today are 350 for H1, H4 and M15. Deviation (c2) compares the last-L-bar value with the all-history value at the last 200 bars that have at least 2,000 bars before them. Thresholds: EMA 0.2 pip (10% of the active 2-pip trend distance), ADX 0.5, RSI 0.5. Frames with less than 2,000 bars are INCONCLUSIVE. Synthetic GBM frames are labelled `model_estimate` and never decide a verdict. Standalone R1 verdict: PASS only if (a), (b), (c1) pass and (c2) passes on at least one real frame and fails on none. |
| V4 | R2 gate order and blocking | 1 `R1A_TRUNCATION`, 2 `R1B_FUTURE_CORRUPTION`, 3 `R1C_WARMUP_PARITY`, 4 `R1C_WARMUP_DEVIATION` (non-blocking), 5 `R2_NO_SAME_BAR_FILL`, 6 `R2_FILLS_WITHIN_BID_ASK`, 7 `R2_NO_FILL_IN_GAP_OR_CLOSED_MARKET`, 8 `R4_COST_STRESS`. PASS only if every blocking check passes. Warm-up deviation does not block because live and replay compute indicators on the same 350-bar windows (proved by check 3); deviation from a long history is a property of the strategy, not a replay defect. Fill ranges are applied literally: a conservative fill outside the bar's quote range (for example a gapped-through target filled at the target) is reported as a failure, not excused. The FX weekly close is Friday 17:00 to Sunday 17:00 America/New_York. |
| V5 | R2 cost criterion | `R4_COST_STRESS` passes when fixed-trade-set expectancy at 2.0× spread+slippage is above 0, i.e. the break-even multiple is above 2.0 (run_replay's harshest existing profile). Zero trades fails with `R4_NO_TRADES`. |
| V6 | Labelling | `verdict.json` carries `verdict` (PASS/FAIL), `evidence_status` (EVIDENCE_ELIGIBLE/NOT_EVIDENCE), `policy_hash`, `dataset_sha256_16`, variant, exit mode and cost. `gate_report.md` starts with `# NOT EVIDENCE: replay failed the authenticity gate` unless the verdict is PASS. A replay report is evidence only with a PASS verdict whose hashes match it. |
| V7 | R4 re-cost model | Per trade `cost_pips = spread_1x + 2 × slippage_1x` (spread from the entry bar for BUY, the exit bar for SELL); `R(m) = r − (m − 1) × cost_pips / stop_pips`; break-even `1 + mean(r) / mean(cost_pips / stop_pips)` when `mean(r) > 0`, else `<=1.0`. Commission stays at 1× unless `--scale-commission` (run_replay's convention). The re-run table re-simulates stage 2 per multiple, so it includes the adversarial spread filter's selection effect. |
| V8 | R5 path model | i.i.d. and circular block bootstrap (block 5) with common random numbers across risk levels. Risk × `LOSS_THROTTLE_STEPS`; trades per day = rounded mean per active UTC day from the trades file; 5 days per week. After each trade, in HardRiskEngine order with `>=`: daily stop skips the day, weekly stop skips to next week, drawdown halt ends the path, a loss streak at `LOSS_HALT_THRESHOLD` resets and skips to next week (the replay's operator reset). All limits come from `get_policy_config(mode_id="core_srs", env={})` and `validation.validate_demo.MAX_DRAWDOWN` (SRS 12.2 acceptance line). Risk grid 1.0–3.0% plus `BASE_RISK_PCT`; 30 and 100 trades. |
| V9 | Fixture outcomes (`tests/fixtures/live_bars_2026-11-03`, GBPUSD and AUDUSD, 400 bars per timeframe) | R1: truncation, both corruption modes and parity PASS on 120 decisions; real-frame deviation INCONCLUSIVE (400 < 2,000 bars); on synthetic 2,400-bar frames EMA(200) at 350 bars deviates 1.3–1.6 pips on H1 and 3.7–6.7 pips on H4 (p95) and needs 750 bars to stay under 0.2 pip; verdict INCONCLUSIVE. R4: 19 trades, expectancy −0.494R at 1×, break-even `<=1.0`; re-run trade counts 19 / 16 / 3 / 0 at 1 / 1.5 / 2 / 3× (commission at 1×). R5: 24 rows; at 3.2% risk and 30 trades P(max DD > 15%) is 0.71 i.i.d. and 0.67 block. R2: FAIL, NOT_EVIDENCE, only blocking failure `R4_COST_STRESS`; all three fill checks PASS. These are fixture numbers (four trading days), not evidence about the strategy. |
| V10 | Follow-up | If R1 (c2) on a full history export shows 350 bars is not enough for EMA(200), the lever is the live fetch length in `core/agents` (regime and technical agents request 350 bars). That change belongs to the agents' owner and must keep live and replay identical; it is not made here. |
