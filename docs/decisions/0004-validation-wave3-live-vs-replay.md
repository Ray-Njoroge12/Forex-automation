# ADR 0004: Validation wave 3: live vs replay

Date: 2026-11-04. Status: proposed, owner review.

Context: assessment `fx_ai_engine/docs/2026-11-03-system-assessment-and-benchmark.md` (§4.3 execution layer, §4.4 validation, §6 step 5 broker realism) and plan `fx_ai_engine/docs/plans/2026-11-03-full-development-and-ai-plan.md` Phase 6 (daily report of spread and slippage at fill; exit criterion "live costs within the replay's 1.5× assumption") and build A2 (daily report without write access to bridge or DB). Branch `research/validation-wave3`, based on `research/validation-wave1` at fa466d8. The tools compare demo-account reality with the replay. They are offline, read-only and report-only: no halt or veto authority, nothing in the engine reads their output, and no cost-model value or risk constant is changed.

Numbering: parallel runs use 0003 (wave 2) and 0005 (wave 4); this ADR keeps 0004.

| W2 | Data sources and read-only rules | The live DB is opened only with the SQLite URI `mode=ro`; the real-data runs read a snapshot taken with `sqlite3` backup from that read-only connection (`tmp/wave3-real/`, gitignored, never committed). | W3 | R7 definitions | Replay fill (unified_replay): a candidate decided at M15 bar close T fills at the open of the bar whose open is T; BUY = bid open + modelled spread + slippage, SELL = bid open − slippage, with modelled spread = max(bar `spread_points`·point/pip, `DEFAULT_SPREAD_FLOOR_PIPS[sym]`) × multiplier and `COST_SCENARIOS['base']` (0.2 pip slippage, 7.00 USD/lot round trip). Strict reference: `replay_execution.market_entry` on the first bar opening strictly after the decision time; reported per deal, not in the verdict. Sign: differences in pips, s = +1 BUY / −1 SELL, positive = worse for the trader than the model. Cost ratio per closed deal = live (actual spread + adverse implied entry slippage + adverse exit slippage + commission / pip value, in pips) / model (modelled spread + slippage, + slippage again for STOP exits, + 7.00 USD / pip value), compared with the Phase 6 limit 1.5×; it has its own status and does not enter the verdict. Strategy deals are matched to `trades` by the deal comment (trade_id), else by trade ticket; other deals (e.g. EA demo-matrix cases) are listed as `NO_STRATEGY_SIGNAL`. |
| W4 | R7 bias rule | Per metric and per symbol: INCONCLUSIVE below 20 comparable deals; otherwise SYSTEMATIC_BIAS when the 95% bootstrap CI of the mean (2,000 resamples, seed 7, fresh generator per aggregate) excludes 0, else NO_SYSTEMATIC_BIAS. The suggested adjustment (slippage = mean implied slippage of the live fills, floored at 0; commission = mean observed round trip per lot; spread floor = p75 of observed spread per symbol) is data only and is marked `actionable` only when the overall verdict is not INCONCLUSIVE. `fill_latency_s` compares against a model latency of 0 s, so it reads as biased whenever fills lag the bar close; read its size. |
| W5 | R8 path model | Wave 1's `research.monte_carlo.resample` with the circular block bootstrap (block 5), 10,000 paths, seed 11, path length = number of live closed trades, resampling the replay trades' `r_multiple` in exit-time order. Bands are in R space: cumulative R per trade index (p5–p95), max drawdown in R and longest loss streak. Live rank = 100·P(sim ≤ live) for the band table and the below-band flag; the above-band flags use 100·P(sim < live) so that ties on the R lattice (+2.2 / −1.0) and on integer streaks do not fire. A replay without an R2 PASS is labelled NOT EVIDENCE. |
| W6 | R8 thresholds and rationale | Minimum 25 live trades, equal to `validation.validate_demo.MIN_TRADES` (SRS §12.2), so drift verdicts start when the acceptance metrics do; below it the verdict is INCONCLUSIVE and flags are informational. Cumulative R below the p5 band: a one-in-twenty false-alarm rate per check, acceptable for a prompt that only asks a human to look. Cumulative R above p99: a result better than almost every simulated path more often means a recording error than skill, so it should alarm rarely. Max drawdown and loss streak above p95: the same one-in-twenty rate as the lower tail. These numbers are version 1, frozen at 2026-11-04T06:34:41Z in commit 894c0db, before the real inputs were copied (7ad5dd0). Any change is a new version in the file plus an amendment to this ADR. |
| W7 | R9 rules and precedence | Primary cause in this order: EXECUTION > NEWS_CALENDAR > SPREAD_COST > REGIME_MISMATCH > ORDINARY_NOISE; all flags are kept. Rationale: an execution anomaly (entry or exit ≥ 1.0 pip worse than the model, fill > 60 s after bar close, exit not placed by the EA, open feedback conflict or uncertain reservation) voids the trade as a test of the strategy; news is exogenous to the model; cost is a known model input; a regime mismatch (losing trades only: ADX within 2.0 of the threshold at entry, or a different regime recorded during the trade) is a strategy question; ORDINARY_NOISE (outcome consistent with the model, nothing abnormal recorded) is the default. The news window is [entry − 30 min, exit + 15 min], equal to `calendar_filter` `BLACKOUT_BEFORE_MINUTES` / `BLACKOUT_AFTER_MINUTES`; windows outside calendar coverage are noted as not evaluable. SPREAD_COST fires at costs ≥ 0.25 R. Pattern claims need at least 10 closed trades in the week; a cause is reported as a pattern at a 25% share (module constant `PATTERN_SHARE`). |
