# ADR 0003: Validation wave 2, multiple-testing correction (R3)

Date: 2026-11-04. Status: proposed, owner review.

Context: assessment `fx_ai_engine/docs/2026-11-03-system-assessment-and-benchmark.md` §4.2 and plan `fx_ai_engine/docs/plans/2026-11-03-full-development-and-ai-plan.md` build E6. Branch `research/validation-wave2-multiple-testing`, based on `research/validation-wave1` at fa466d8. The tool is offline and read-only: it reads the experiment registry and replay outputs, never runs a replay, never places, sizes or routes orders, never writes to the bridge folder and never changes a risk constant.

Numbering: waves 3 and 4 run in parallel and use ADR 0004 and 0005. If `hardening/2026-11` adds an ADR 0003 before this branch merges, renumber this file at merge.

| M2 | Inputs found and what is missing | Registry rows (`run_replay.py`) carry `run_id, variant, cost, policy_hash, datasets, dev{trades, win_rate, expectancy_r, profit_factor}, dev_max_dd, holdout{…}, report`, plus an optional `superseded: true`. They carry no per-trade series and no standard deviation, skew or kurtosis, so neither DSR nor CSCV can be computed from the registry alone. The series come from `<stem>_trades.csv` next to each `report` (`entry_time`, `r_multiple`), bound to the row by `<stem>.json` (`generated_at` = `run_id`, same `policy_hash` and `cost`) and by dev/holdout counts equal to the registry's. On the real registry (57 rows) 21 rows have a matching series. Missing: the 18 superseded rows of run `20261103T175026Z` for baseline, coded_defaults and pullback_2, whose files in the shared `artifacts/replay/2026-11-03_edge/` directory were overwritten by run `20261103T184434Z`; and the 18 rows of `rsi_bounded`, `adx_20_25` and `trend_distance_5pip` (× 3 exit modes × 2 costs), which have only superseded rows and no trade files at all. Rows without a series count toward N and are INCONCLUSIVE `SERIES_FILES_MISSING`; the tool fails closed rather than estimating their statistics. |
| M3 | Trials, row selection, groups | A trial is a distinct `(policy_hash, exit_mode)` pair over all parseable rows, whatever the cost, halts mode or superseded flag; stress-cost runs re-cost the same configuration and are not extra trials. Labels are parsed as `<variant>__<exit_mode>[__<halts>]` (this branch's run_replay writes the first two parts, hardening's adds `__<halts>`); a second part outside `unified_replay.EXIT_MODES` makes the whole label the exit mode. Real registry: 6 policy hashes × 3 exit modes, **N = 18**. Evaluated rows: per `(label, cost)` the last row in file order without `superseded`, else the last row; the rest are listed as `superseded_rows` (real: 39 evaluated, 18 listed). Cross-trial statistics are computed per group `(halts, cost)`: SRS-halt runs (flat after the first halt), edge runs and different cost profiles are not comparable return streams; mixing them made the halted SRS run the IS and OOS winner of every CSCV split in the planning prototype. |
| M4 | Deflated Sharpe ratio | Development trades only (`entry_time < holdout_start`), unit `r_multiple` per trade. `SR = mean / std(ddof=1)`; skew `g3` = `scipy.stats.skew(bias=True)`; kurtosis `g4` = `scipy.stats.kurtosis(fisher=False, bias=True)` (Pearson, normal = 3); `T` = dev trades. `PSR(SR*) = Φ((SR − SR*)·√(T − 1) / √(1 − g3·SR + (g4 − 1)/4·SR²))`; std 0 or a denominator ≤ 0 is `DSR_UNDEFINED`. `SR0 = √V·((1 − γ)·Φ⁻¹(1 − 1/N) + γ·Φ⁻¹(1 − 1/(N·e)))`, γ = Euler–Mascheroni, `V` = variance (ddof=1) of the per-trade SR over the group's valid series (≥ 2 needed), `N` = registry-wide trial count; `SR0 = 0` when N < 2. `DSR = PSR(SR0)`, PASS needs `DSR ≥ DSR_MIN = 0.95`. Because `SR0 ≥ 0` for N ≥ 2 and PSR falls as SR* rises, `DSR ≤ PSR(0)`, so `PSR(0) < 0.95` is a sound FAIL (`PSR_BELOW_MIN`) whatever V is, even when V cannot be computed. |
| M5 | CSCV / PBO | Per group: rows are FX weeks, columns the group's valid series. Each dev trade is bucketed by `entry_time` in America/New_York plus 7 hours as a `W-SUN` period, so the week opens Sunday 17:00 New York (ADR 0002 V4). Cells are the week's summed `r_multiple`, 0 for no trades. The grid runs from the `development.range` start date to the week before `holdout_start`; series with a different start or `holdout_start` give `CSCV_GRID_MISMATCH`. `S = 16` contiguous blocks (`numpy.array_split`), all C(16, 8) = 12,870 IS/OOS splits; metric = Sharpe of weekly sums (std 0 gives 0); the IS best is `argmax` (first column on ties); its OOS relative rank `ω = rankdata(OOS, average) / (N_g + 1)`, `λ = ln(ω / (1 − ω))`, `PBO = mean(λ ≤ 0)`. Needs ≥ 2 series (`GROUP_TOO_FEW_SERIES`) and ≥ 64 weeks, 4 per block (`CSCV_TOO_SHORT`). PASS needs `PBO ≤ PBO_MAX = 0.20`: at most one split in five picks a configuration that lands at or below the OOS median. 0.5 is selection no better than chance; 0.20 is a stricter policy choice the owner may adjust. |
| M6 | Minimum sample | A PASS needs dev trades ≥ `N_MIN = 307`, computed in code by `min_sample_design`. Target expectancy μ = +0.25R (plan decision D2). Binary model: reward R = `MIN_RISK_REWARD` = 2.2 (read from `get_policy_config(mode_id="core_srs", env={})`) against −1R; the win rate giving μ is `q = (μ + 1)/(R + 1) = 0.390625`; `σ = (R + 1)·√(q(1 − q)) = 1.5612`. A two-sided 95% CI that excludes zero with 80% power when the true mean is μ needs `n = ((z0.975 + z0.80)·σ/μ)² = ((1.9600 + 0.8416)·1.5612/0.25)² = 306.1`, rounded up to 307. Rejected: the CI-only size `(1.96·σ/μ)² = 150`, which a variant at exactly the target clears only half the time. Measured dev σ on the real edge series is 1.06 to 1.49 (SRS series 0.68 to 0.84), all below 1.5612, so the design σ is conservative for the current exit modes. Valid series below N_MIN still count in V and CSCV. |
| M7 | Order of checks and overall rule | Per row, first match wins: 1 `SERIES_FILES_MISSING`, `SERIES_UNREADABLE`, `SERIES_RUN_MISMATCH`, `SERIES_COUNT_MISMATCH` (also catches a file still being written), INCONCLUSIVE; 2 `BELOW_MIN_SAMPLE`, INCONCLUSIVE; 3 `DSR_UNDEFINED`, INCONCLUSIVE; 4 `PSR_BELOW_MIN`, FAIL; 5 `GROUP_TOO_FEW_SERIES`, `CSCV_TOO_SHORT`, `CSCV_GRID_MISMATCH`, INCONCLUSIVE; 6 `GROUP_SERIES_INCOMPLETE` (a configuration in the group has no valid series, so V and PBO would omit trials that were part of the search), INCONCLUSIVE; 7 `DSR_BELOW_MIN`, FAIL; 8 `PBO_ABOVE_MAX`, FAIL; 9 PASS. Overall: INCONCLUSIVE if the registry is missing or empty (`REGISTRY_MISSING`, `REGISTRY_EMPTY`) or any line fails to parse (`REGISTRY_LINE_UNPARSEABLE`, e.g. a partly appended row); else PASS if any row passes, else INCONCLUSIVE if any row is INCONCLUSIVE, else FAIL. CLI exit code 0 on PASS, 1 otherwise. |
| M8 | Labelling | `verdict.json` (`tool: r3_multiple_testing`) carries `verdict` (PASS/FAIL/INCONCLUSIVE) and `evidence_status`, `EVIDENCE_ELIGIBLE` only for PASS, else `NOT_EVIDENCE`, overall and per row, plus `registry_sha256_16` and per-row file hashes. `report.md` starts with `# Multiple-testing check (R3): PASS` or `# NOT EVIDENCE: no variant passed the multiple-testing check (R3)`; the per-row `evidence` column reads `EVIDENCE_ELIGIBLE` or `NOT EVIDENCE`. An R3 PASS is necessary, not sufficient: the replay still needs an R2 gate PASS with matching hashes (ADR 0002 V6). |
