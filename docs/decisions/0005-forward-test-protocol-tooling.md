# ADR 0005: Forward-test protocol tooling (validation wave 4, R10)
Date: 2026-11-04. Status: proposed, owner review.
Context: plan `fx_ai_engine/docs/plans/2026-11-03-full-development-and-ai-plan.md` Phase 3 (SRS v1.1; item 6 freezes the configuration hash) and Phase 6 (no-change rule, abort and exit criteria), and assessment `fx_ai_engine/docs/2026-11-03-system-assessment-and-benchmark.md` §4.2. Branch `research/validation-wave4-forward-test`, based on `research/validation-wave1` at fa466d8. The tools are offline and read-only: they never place, size or route orders, never write to the bridge folder and never change a risk constant, the SRS or the EA.
Numbering: 0005 was assigned to this wave; parallel waves use 0003 and 0004.
| # | Decision | Adopted |
| --- | --- | --- |
| F1 | Location | New subpackage `fx_ai_engine/research/forward_test/` (`freeze`, `prereg`, `evaluate`). Tests in `fx_ai_engine/tests/test_research_forward_*.py`, fixture `tests/fixtures/forward_test/demo_trades.sql` (synthetic). Starter criteria `fx_ai_engine/docs/research/forward-test/criteria-srs-v1.1-draft.json` (DRAFT, not approved). Draft SRS v1.1 proposal `fx_ai_engine/docs/2026-11-04-srs-v1.1-draft-proposal.md`. Skill `.kiro/skills/fx-forward-test-protocol/SKILL.md`. No existing file is edited. |
| F2 | Freeze manifest (`fx-forward-freeze/1`) | Records: the policy hash from running `validation.print_policy_hash --mode core_srs --json` as a subprocess in the target checkout (so another checkout, such as the one the engine runs from, can be frozen); sha256 of `config_microcapital.py`; sha256 of `mt5_ea/FX_Execution.mq5` and its pinned `ExpectedPolicyHash`; sha256 of the compiled `.ex5` (default: the terminal's `MQL5/Experts/FX_Execution.ex5`, read-only); sha256 of every `.py/.mq5/.mqh/.md` file under the AGENTS.md protected paths, so bridge runtime json/lock files are excluded; and `git rev-parse HEAD`. A `manifest_sha256` over the canonical body detects edits. Create refuses without a policy hash, config or EA source. A missing build or commit is recorded as null and warned about, never guessed. |
| F3 | Freeze check reason codes | One entry per code and item: `POLICY_HASH_CHANGED`, `POLICY_HASH_UNAVAILABLE`, `CONFIG_HASH_CHANGED`, `CONFIG_MISSING`, `EA_SOURCE_HASH_CHANGED`, `EA_SOURCE_MISSING`, `EA_PIN_POLICY_MISMATCH` (current pin vs current policy), `EA_BUILD_HASH_CHANGED`, `EA_BUILD_MISSING`, `PROTECTED_FILE_CHANGED/ADDED/REMOVED`, `GIT_COMMIT_CHANGED`, `GIT_COMMIT_UNAVAILABLE`. Every mismatch makes the verdict MISMATCH (fail-closed). A commit change may or may not change behaviour; the owner decides whether it restarts the clock. `INVALID_MANIFEST` covers `MANIFEST_SCHEMA_UNSUPPORTED` and `MANIFEST_DIGEST_MISMATCH`. |
| F4 | Criteria format (`fx-forward-criteria/1`, JSON) | Fields: `criteria_id`, `criteria_version`, `status` (`DRAFT_NOT_APPROVED`/`APPROVED`), `approved_by`, optional `freeze_manifest_sha256`, `scope` (policy/execution mode, evidence stream, account scope), `sample.min_closed_trades`, `sample.min_trading_days`. `go[]` and `abort[]` criteria have `{id, metric, op, value, min_trades, status, source}`, where status is one of `PROPOSED_IN_PLAN_NOT_APPROVED`, `SRS_V1_UNCHANGED`, `OPEN_OWNER_DECISION` or `APPROVED`. `manual_checks[]` holds the Phase 6 conditions the DB cannot show. A null value is allowed only for `OPEN_OWNER_DECISION`. An APPROVED file must have `approved_by` and only APPROVED, non-null criteria. Metric names are a fixed list (`prereg.METRICS`). |
| F5 | Seal (`fx-forward-seal/1`) | `prereg seal` stores the criteria sha256, id, version, status, `start_utc`, `sealed_at_utc` and a `seal_sha256`. The start must be after the seal time; `--allow-backdate` exists for demos and marks the seal `backdated`, which makes every evaluation `decision_grade: false`. `verify` refuses on `SEAL_SCHEMA_UNSUPPORTED`, `SEAL_DIGEST_MISMATCH`, `SEAL_AFTER_START`, `CRITERIA_MISSING`, `CRITERIA_INVALID`, and on a content change: `CRITERIA_MODIFIED_AFTER_START` when the mtime is after the start, otherwise `CRITERIA_HASH_MISMATCH`. The hash is authoritative; an mtime change alone only warns. Limitation: whoever can rewrite both files can forge a seal, so the criteria file and the seal are committed before the start and the commit is the anchor. |
| F6 | Evaluator | The DB is opened with `sqlite3` URI `mode=ro` (or a copy is used). It counts `CLOSED*` trades with `close_time` in [start, as-of], parsed in Python because the DB mixes `+00:00` and `Z` timestamps; equity samples in the same window; and all unresolved `execution_feedback_conflicts`. Metrics are reused, not redefined: `validation.validate_demo._compute_metrics` (SRS win rate r > 0, average R, average winner R, equity drawdown) and `backtesting.replay_report.trade_metrics` (expectancy, bootstrap CI, profit factor in account currency, average winner/loser with the ±0.1R band, longest losing run). Wave 2 is not on this base, so none of its code is used. `trading_days_elapsed` is `numpy.busday_count(start, as_of)`. If every trade has zero PnL, profit factor is reported as null, not as infinity. Verdict order: REFUSED > INVALID (freeze mismatch, or a manifest other than the one named in the criteria) > ABORT > INCONCLUSIVE (sample or window below minimum; open or uncomputable go criterion) > NO_GO > GO (manual checks pending). Exit code 0 only for GO, 2 for REFUSED, 1 otherwise. |
| F7 | Starter criteria (DRAFT) | G1–G3 use the plan's D2 defaults (expectancy ≥ +0.25R, PF ≥ 1.3, average winner ≥ 1.5R), labelled proposed in plan, not approved. G4 (win rate ≥ 45%), G5 (drawdown ≤ 15%), A1 (drawdown > 20%) and A2 (win rate < 40% from 25 trades) are SRS v1 unchanged, and tests tie them to `validate_demo`'s constants. G6 is zero unresolved feedback conflicts (Phase 6 exit). A3, the replacement for the §12.3 avg-R abort, is open. The minimum is 25 closed trades (SRS v1; plan says raise or relabel) and 30 trading days. Manual checks M1–M7. |
| F8 | Owner decisions left open | The proposal leaves open D2, D3, O1 (minimum trades), O2 (win-rate gates), O3 (point estimate vs CI), O4 (2 trades vs 5% cap) and O5 (avg-R abort replacement). It also leaves open G2-START: by gate G2 no 30-day demo should start on negative replay expectancy, and the 2026-11-03 batch is negative for every finished variant (baseline −0.347R dev over 5,622 trades, −0.355R holdout over 784, PF 0.47). ADR 0001 records the owner accepting the plan defaults; the brief for this wave treats D2/D3 as unanswered, and the proposal flags that so the owner can resolve it. |

Outputs are in `fx_ai_engine/artifacts/research/forward-test-demo/`. The R5 sweep on the baseline replay trades is in `artifacts/research/forward-test-evidence/`. |
| F10 | Known gaps | Strategy code outside the protected paths (`core/agents`) is covered only by the git commit check, so uncommitted edits there are not seen. Extending the frozen path list is a protocol decision for the owner. The policy hash depends on the environment of the process that runs the check, which should be the engine's (launchd) environment. Reading a WAL database touches its `-shm` file, as any SQLite reader does. |
