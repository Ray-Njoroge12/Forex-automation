**Status: proposal, owner approval required; no constant changed.** `SRS_v1.md` and `fx_ai_engine/config_microcapital.py` are unchanged. The SRS v1 locked constants (3.2% risk per trade, 2 open trades, 5% combined exposure, 8% / 15% / 20% stops, 3-loss halt, R:R ≥ 2.2) stay in force until the owner approves this text and the change is made as described in section 5.

- Date: 2026-11-04. Branch `dev/development-wave`, plan stage F (plan Phase 3, gate G3).
- Decisions used: ADR 0001 (`docs/decisions/0001-development-plan-defaults.md`) D2, D3 and D6, with D1, D4 and D5 for the host, data and account rows. The owner accepted these defaults on 2026-11-03 ("use defaults"). ADR 0001 sets the direction; the SRS text below still needs owner approval (G3).
- Owner direction since ADR 0001: ADR 0007 (no 30-day demo; demo testing in owner-started test waves, one frozen release each). ADR 0007 is on `hardening/2026-11`, not yet on this branch.
- Related draft: `fx_ai_engine/docs/2026-11-04-srs-v1.1-draft-proposal.md` on `hardening/2026-11` (validation wave 4). That draft treated D2 and D3 as unanswered and listed options O1 to O5. This proposal applies ADR 0001 and gives one proposed text per item; it keeps the O-numbers so the two can be read side by side. After the merge, this document is the one to approve.
- Evidence: `docs/STATUS.md` "Phase 2 result"; `fx_ai_engine/artifacts/replay/2026-11-03_edge_diagnostics.json`; replay reports in `fx_ai_engine/artifacts/replay/2026-11-03_edge/` (main checkout, untracked) and `fx_ai_engine/artifacts/replay/2026-11-03_srs/` (tracked); R5 sweep `fx_ai_engine/artifacts/research/r5/2026-11-04_srs_v11/monte_carlo.md` (run for this proposal). ### 1.3 Sample size

Standard deviation of R over the 6,406 replay trades: 1.09R. Standard error of mean R: 0.22R at 25 trades, 0.15R at 50, 0.11R at 100. About 118 closed trades give 80% power to detect a true +0.25R against zero (one-sided, 5%); about 198 with the k = 3 family correction used in the Phase 2b cards (z = 2.39). 25 trades cannot separate a 35% from a 45% win rate.

## 3. Notes on specific changes

**C7 risk per trade.** ADR 0001 D3 keeps 3.2% only if Phase 2 shows the drawdown gate is reachable. It is not: with the SRS halts on, the replay hits the 20% hard halt within 7 days of the first trade (2022-12-27 to 2023-01-03), and the R5 sweep gives a 0.90 to 0.92 chance of a drawdown above 15% within 100 trades at 3.2%. The proposed range is the D3 default. The numbers in §1.2 come from a losing strategy; the value is fixed by rerunning R5 on the frozen Phase 2b strategy. A change to `BASE_RISK_PCT` changes the `core_srs` policy hash, so the EA pin and the release freeze manifest are redone in the same change (section 5).

**C8 exposure.** No limit changes. Lowering risk to 1.0 to 1.5% removes the conflict, because two full-size trades fit under the 5% cap.

**C12 and STATUS known issue 17.** Two existing gates can reject routes today: `ML_RANKER_LOW_PROB` when a ranker model file exists (absent now), and the strict canary when `FX_META_LABELER_CANARY_ENABLED` and mode `strict` are set (off by default). Both only reject, but under C12 they are promoted behaviour and run after the Hard Risk Engine. Proposed: keep both disabled by policy (no model file, canary off) until a component passes the C12 promotion rule. The owner may instead ask for them to be made log-only; that is a code change for a later wave.

**C13 pre-live gate.** ADR 0007 removed the 30-day demo from development but left the real-money gate open. The proposed text is one option; real money stays a separate owner decision in any case.

**C15 and C16 thresholds.** A gate set at the target value (+0.25R) passes a strategy whose true expectancy equals that value about half the time, whatever the sample. The proposal gates on the point estimate, as D2 states, and requires the C15 minimum so the estimate has a standard error near 0.10R. Gating on a confidence bound (O3) is the stricter alternative; it is not proposed.

## 5. Implementation after approval (not done in this proposal)

1. Create `SRS_v1.1.md` (or edit `SRS_v1.md` with a version bump) with the approved text. `SRS_v1.md` is a protected path: second-model review and owner approval before merge.
2. Change `BASE_RISK_PCT` in `fx_ai_engine/config_microcapital.py` (protected path) and update `fx_ai_engine/tests/test_srs_locked_constants.py` and the CI constant check to the v1.1 values in the same commit.
3. Print the new policy hash (`python -m validation.print_policy_hash --mode core_srs`), update the EA's `ExpectedPolicyHash` (`fx_ai_engine/mt5_ea/**`, protected), compile, and deploy only with owner approval.
4. Add the v1.1 metrics (C15, C16, C18) to `validation/validate_demo.py` next to the v1 ones, and write the release criteria file for `research.forward_test.prereg` from the approved values.
5. Freeze the first Phase 2b release with `research.forward_test.freeze create` and record its configuration hash in the SRS (C20).

## 6. What this proposal does not change

No SRS text, risk constant, strategy parameter, EA input, CI check or policy hash is changed by this document. `validation.validate_demo` keeps evaluating SRS v1 §12 as written. The AGENTS.md invariants are unchanged: only the EA places orders, the Hard Risk Engine has the final say, AI runs in shadow only.
