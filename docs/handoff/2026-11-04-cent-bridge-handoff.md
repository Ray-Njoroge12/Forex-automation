3. **`check_bridge_health.py`: done on `cent/integration-fixes` (BR-006).** `check_snapshot_health` now returns the balance in dollars through `account_unit_scale`, so 1000 USC prints `$10.00`. A snapshot with no currency gives `balance` None and the CLI prints that the balance is unavailable (the mock simulator's snapshot counts as dollars).
4. **`validation/validate_demo.py` (`PRESERVE_10_CRITICAL_TRADE_REASONS`, line 65, used by `_count_trade_reasons`, line 183) and `analyze_tendencies.py` (`DEPLOYABILITY_REASON_CODES`, line 15).** Decide whether `REJECTED_SYMBOL`, `REJECTED_ACCOUNT_MODE` and `REJECTED_LIVE_GUARD` count as critical or deployability reasons. 5. **`main.py` (Policy-Live).** No change needed for units: Preserve-10 facts stay raw plus `unit_scale` (ADR 0012 section 2), and `FIXED_RISK_USD` is dollars and now correct on cent accounts. `FileBridgeConnection.get_ea_profile()` exposes `live_guard`, `account_margin_mode`, `account_currency` and `max_spread_pips_input` (None when the EA does not export them) for a live guard. `symbols_ok` false fails these readers with `FILE_BRIDGE_SYMBOLS_NOT_OK`: connect, `server_utc_offset_seconds`, account snapshot (and so `is_demo_account` and both `evaluate_*` checks), position tickets, OHLC, `get_live_spread` and `get_symbol_execution_contract` (the last two were added by review finding BR-005). Intentionally ungated: `get_position_history_summary` and `get_trade_history_summary` (they report deals already booked and reconciliation must continue; they need currency evidence instead) and `get_ea_profile` (the checker and a live guard must be able to read `symbols_ok` and `symbol_errors`). A non-empty `symbol_errors` gates even when `symbols_ok` is absent. Reasons and the EA evidence are in ADR 0012 section 4.
6. **EA track (`mt5_ea/FX_Execution.mq5`).** Confirm: (a) `account_margin_mode` representation (string such as `ACCOUNT_MARGIN_MODE_RETAIL_HEDGING`, or the MT5 int 0/1/2; both are accepted by `file_bridge_check`); (b) `live_guard` is a JSON object, `symbol_errors` a list of strings, `max_spread_pips_input` a number >= 0, `symbol_suffix` a string (empty allowed); (c) `symbols.json` entries carry `broker_symbol` equal to canonical name + `symbol_suffix`, while file names and bar payload `symbol` stay canonical; (d) status `account_currency` equals the snapshot `currency`; (e) the EA writes `REJECTED_SYMBOL`, `REJECTED_ACCOUNT_MODE`, `REJECTED_LIVE_GUARD` with ticket 0. Only if Preserve-10 on the file bridge is wanted later: export `leverage` and per-symbol margin for the minimum lot (`OrderCalcMargin`); `account_trade_allowed` is already exported.

10. **Review fixes BR-001 to BR-006 (branch `cent/integration-fixes`, base `861ea02`).** Detail in ADR 0012 sections 4 and 7.
    - BR-001 `bridge/execution_feedback.py`: the cached unit scale starts unknown. Until a readable snapshot names a non-empty currency, `collect_execution_feedback`, `collect_trade_exits` and the `consume_*` wrappers return nothing, log a warning and leave valid artifacts in place. Malformed and schema-invalid files are still quarantined (moved, not deleted). USD, EUR and USC snapshots resolve on the first poll. Mock runs: payloads tagged `feedback_source: mock_feedback_simulator` count as known USD when no snapshot currency exists, only while `allow_mock_artifacts` is true.
    - BR-002 `core/mt5_bridge.py`, `core/file_bridge_connection.py`: `_unit_scale()` returns `None` and sets `MT5_ACCOUNT_CURRENCY_UNAVAILABLE` or `FILE_BRIDGE_ACCOUNT_CURRENCY_UNKNOWN`; position and trade summaries and `get_symbol_execution_contract` then return `None` and retry on the next poll. The file bridge takes and caches a currency only from a fully validated account snapshot (the same validation as account reads, minus the `symbols_ok` gate); status `account_currency` alone is not evidence.
    - BR-003 `read_execution_feedback()` returns the normalised payloads of `collect_execution_feedback()`.
    - BR-004 `research/demo_records.resolve_units` raises `UnitsUnknownError` without `--account-currency` or a `status.json` `account_currency`; `fill_reconciliation`, `drift_monitor` and `trade_postmortem` exit with code 2 and write nothing. Copies that previously relied on the silent USD default need `--account-currency USD` or a `status.json` beside `deals.json`.
    - BR-005 and BR-006: see item 5 and item 3.
    - **`application/**` and `main.py` caller change: none required.** `main.py` line 625 already builds the reader with `allow_mock_artifacts=self.use_mock`, which the mock rule relies on; the reader works through its existing constructor and attributes. A single `account_currency` constructor argument would be the only alternative and would be a new reader parameter, so it is not proposed.
    - Left open: `FileBridgeConnection.get_account_snapshot` and `ExecutionFeedbackReader.read_account_snapshot` still treat a snapshot with no `currency` as scale 1.0 (the EA always writes `currency`, `FX_Execution.mq5` line 1255; the mock simulator's snapshot has none). Closing that needs a decision on old-EA bridges and the mock path, so it was not changed in this fix.
